# Development Guide

## Purpose

This document is the operational reference for installing, running, and changing the project. For system ownership and runtime flow, see [Architecture](ARCHITECTURE.md).

## Prerequisites

- Node.js `^20.19.0` or `>=22.13.0` (ESLint 10 needs `22.13` on the 22 line).
- pnpm `9.15.9`, as declared by the `packageManager` field in `package.json`.
- A browser with WebGL support.

Use pnpm for dependency changes. Do not introduce a second lockfile.

## Commands

```bash
pnpm install
pnpm dev
pnpm test
pnpm lint
pnpm format
pnpm format:check
pnpm build
pnpm preview
pnpm assets:encode
pnpm bench
```

- `pnpm dev` starts Vite with network access through `--host`.
- `pnpm test` runs the Node test suite with `--import ./test/support/register.mjs`, whose hooks let tests import modules written for Vite: extensionless relative imports, `.glsl` files (their source string), and `?url` assets (their path).
- `pnpm lint` runs ESLint ([`eslint.config.js`](../eslint.config.js): the recommended correctness rules with browser, worker, and Node globals per folder, no formatting rules).
- `pnpm format` rewrites the code with Prettier ([`.prettierrc.json`](../.prettierrc.json): tabs, no semicolons, single quotes, trailing commas, `100` columns; JSON with two spaces); `pnpm format:check` only checks. Markdown, generated output, and assets are excluded ([`.prettierignore`](../.prettierignore)): Prettier would pad every cell of the guides' long tables.
- `pnpm build` creates the production bundle in `dist/`.
- `pnpm preview` serves the production bundle locally.
- `pnpm assets:encode` re-encodes the masters in `assets-src/` into the KTX2 textures in `src/textures/`, the airplane GLBs in `public/plane-toy/` and their simplified shadow casters (`*-shadow.glb`), and the boat's two simplified levels in `public/boat-toy/boat.glb` (see [Assets](ASSETS.md#encoding-pipeline)). It needs `basisu` from Basis Universal 2.x on `PATH` (`brew install basis_universal`); commit its outputs. The app itself needs no extra tool.
- `pnpm bench` builds the working tree (and, with `--compare <git-ref>`, that ref in a temporary worktree), serves each build, and measures it in headless Chrome (muted, `--mute-audio`) with a deterministic flight; `--shots <dir>` also saves held captures and prints the PSNR between builds. It needs Node 22 or later and Chrome (`--chrome` or `CHROME_PATH` elsewhere than the default install path); `pnpm bench --help` lists the options. See [Comparing Builds](QUALITY.md#comparing-builds).
- Use the URL printed by Vite; the default port may change when it is already occupied.

Do not edit or commit generated files under `dist/`.

## Current Toolchain

- Vite builds the ES-module application.
- `vite-plugin-glsl` makes GLSL files importable by JavaScript.
- `postprocessing` (pmndrs) provides the effect composer; its `three` peer range must include the installed Three.js version.
- Tailwind CSS is processed through `@tailwindcss/postcss`.
- Textures and the airplane and boat GLB textures are KTX2 (Basis ETC1S). three's `KTX2Loader` transcodes them with its own `basis_transcoder.js` and `.wasm`, which Vite bundles. `@gltf-transform/core`, `@gltf-transform/extensions`, and `meshoptimizer` are dev dependencies used only by `scripts/encode-assets.mjs`.
- The application is plain JavaScript. There is no TypeScript compilation step.
- Node's built-in test runner runs `test/*.test.js`; [Quality](QUALITY.md#required-checks-by-change) lists what each suite covers.
- Vite bundles `src/chunkGeometry.worker.js` as a module worker; no separate worker build command is required.
- [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) runs `pnpm lint`, `pnpm format:check`, `pnpm test`, and `pnpm build` on Node 22 for every push and pull request. There is no browser test suite.

See [Quality](QUALITY.md) for the browser and rendering validation that remains outside the pure Node tests.

## Code Conventions

Follow the patterns in the code being changed rather than introducing a parallel style.

- Use ES modules and preserve the existing default-export class boundaries.
- Prettier owns the formatting (tabs, no semicolons); run `pnpm format` before committing.
- Keep Three.js object ownership explicit. The bootstrap belongs in `main.js`, world construction and the frame loop in `World`, the renderer and its pipeline in `RenderSetup`, startup assets in `assetLoader.js`, and the DOM flow in `Intro`; terrain lifecycle belongs in `ChunkManager` and `Chunk`; runtime flight behavior belongs in `Plane` and its parts, while scalar flight rules belong in `flightPolicy.js`. [Architecture](ARCHITECTURE.md#runtime-map) maps every module.
- Pure modules (policies, placement, terrain buffers) import no three.js objects or browser state, so Node tests and the chunk workers can run them. They share [`src/math.js`](../src/math.js) (`clamp01`, `lerp`, `smoothstep` with three's formulas), [`src/random.js`](../src/random.js) (seed hashing, cell randomness, weighted picks), and [`src/noise.js`](../src/noise.js) (the GLSL simplex port) instead of local copies.
- Keep worker messages structured-cloneable. Transfer generated typed-array buffers, and create or mutate renderer-owned objects only on the main thread.
- Reuse vectors and matrices in frame-sensitive code where the surrounding module already does so. Avoid allocations inside the render loop without measuring their cost: policy functions called every frame take an optional `out` object that the caller passes again each frame (`getFlightCorridor()`, `selectShadowLight()`, `getDayNightState()`).
- Uniform names use a `u` prefix, such as `uTime` and `uCamera`.
- Keep shader source in `src/shaders/`; do not embed large GLSL strings in JavaScript. A GLSL helper used by several chunks gets its own file with an `#ifndef` include guard (`curvature-drop.glsl`, `rotate-yaw.glsl`, `interleaved-gradient-noise.glsl`), because one program can include it twice. Constants the CPU also needs come from JavaScript as material defines (`TERRAIN_SHADER_DEFINES`), not as GLSL literals.
- Tests import source modules through the hooks in `test/support/`, so extensionless relative imports, `.glsl`, and `?url` imports work in Node too. Modules that also run outside the test runner in Node (`scripts/`) keep explicit `.js` extensions.
- Patch built-in shaders only with `replaceChunks()` ([`src/shaderChunks.js`](../src/shaderChunks.js)), never with a bare `String.replace()`, and add new patches to `test/shaderPatches.test.js`.
- Preserve responsive behavior at the existing `768px` JavaScript breakpoint unless a task intentionally redesigns it.
- Add comments only for constraints or non-obvious behavior.

## Change Workflow

1. Read the topic guide linked from the root `AGENTS.md` and the owning source module.
2. Make the smallest change that preserves existing ownership boundaries.
3. Run `pnpm test` and `pnpm build` after every source, shader, dependency, or configuration change.
4. Perform the change-specific checks in [Quality](QUALITY.md).
5. Update the relevant guide when behavior, commands, architecture, or asset requirements change.

When updating dependencies, keep `package.json` and `pnpm-lock.yaml` in sync and review upstream migration notes for Three.js, `postprocessing`, Vite, Tailwind CSS, and `vite-plugin-glsl`.

## Debugging Notes

- The scene starts rendering only after the loading manager completes and `World.init()` schedules the first animation frame.
- Browser console errors and failed network requests are the first checks when the page remains on the loader. A failed airplane load shows the load-error state instead (see [Experience](EXPERIENCE.md#loading-flow)).
- Shader compilation failures appear in the browser console, not necessarily during `pnpm build`.
- The optional `lil-gui` panel ([`src/debug/debugGui.js`](../src/debug/debugGui.js)) is enabled only with `?gui=1`, which is also the only case that downloads it (a top-level dynamic `import()` of the module, which bundles `lil-gui`). Its controls edit `params` and call the owning system (`World`, `RenderSetup`, or a world system); before the world is built they only edit `params`. Every folder starts closed. The **World** folder shows the world **Seed**. Editing it and pressing Enter (or leaving the field) regenerates terrain, biomes, and scenery with that seed; a blank value restores the current one. **Seed list** switches to one of the curated seeds (`CURATED_SEEDS` in [`src/worldSeed.js`](../src/worldSeed.js)), and **Random seed** picks a new random one. The URL is not updated, so copy the value into `?seed=` to reproduce the world. The **Biomes** folder has one folder per biome and the [biome map](EXPERIENCE.md#debug-biome-map) in the top-left corner, which the GUI owns: **Distribution** sets **Biome size ×**, **Desert share**, **Ice size ×**, **Ice rarity**, and **Forest ring** (live on the terrain colors and the map; releasing a control regenerates terrain and scenery; see [Biome Field](TERRAIN.md#biome-field)); **Map** shows or hides the map, follows the airplane, and resets the view (a double click on the map teleports the airplane there); **Forest**, **Desert**, and **Ice** each hold their **Terrain palette** (a color per land band, **Light patches ×**, **Band lines**, and a **Variation** color and amount per band, live), their **Rock colors** (boulders and sea rocks, plus layered rocks in the desert and ice spikes in the ice, live), and, for the forest, the **Tree palette**, for the desert, the **Cactus palette** and **Topography** (desert detail-octave frequency and amplitude multipliers, the blend width, and the progressive **Height reduction** with its **Reduction depth** in climate units; releasing a control regenerates the chunks), and, for the ice, its **Topography** (detail frequency and amplitude, at most `1`, blend width, the plain's **Height reduction** and **Reduction depth** in ice field units, and the mountains' **Peak height**, at most `85`, **Peak spacing**, **Peak chance**, **Peak radius**, and **Peak sharpness**; releasing regenerates) and **Frozen sea** (sheet depth, night growth, taper, floe band and its night growth, floe size, cracks and their night closing, edge wobble, and colors, live; see [Sea Ice](RENDERING.md#sea-ice)); **Sea** sets the shallow, open, and deep sea colors live. With the GUI enabled, the play action does not start the soundtrack, and until Play the airplane stays still, without turning (see [Experience](EXPERIENCE.md#play-action)).
- `?time=<0..1>` sets the starting time of day (`0` midnight, `0.25` sunrise, `0.5` noon, `0.75` sunset). Without it, or with an invalid or out-of-range value, the cycle starts at the user's local clock time (`getLocalTimeOfDay()`: a load at midnight starts at `0`, at 18:00 at `0.75`), or at a fixed `0.3` with `?debug=1` or `?gui=1` (`DAY_NIGHT_DEFAULTS.debugTimeOfDay`). Combine it with `?seed=` for reproducible visual checks.
- `?aurora=<0..1>` sets the aurora's chance per roll (clamped; an invalid value keeps the default `0.4`): `?aurora=1` gives an aurora on every roll and `?aurora=0` none. With `?seed=ice194&time=0.9&aurora=1` the flight starts in the ice at night under an aurora.
- `?clouds=<0..1>` holds the share of the horizon the [horizon clouds](RENDERING.md#horizon-clouds) cover (clamped; an invalid value keeps the drifting weather), for QA and benchmarks: `?clouds=0` leaves the horizon almost clear (the threshold keeps the share between `0.01` and `0.99`), `?clouds=0.95` nearly fills it.
- `?seed=<value>` fixes the world seed for topology, biomes, and scenery. The value is trimmed, and a blank or missing value falls back to one of the curated seeds (`CURATED_SEEDS` in [`src/worldSeed.js`](../src/worldSeed.js)), picked at random on every load.
- `?plane=<key>` picks the airplane model from `AIRPLANE_MODELS` in `src/airplaneModels.js`: `biplane` (default) or `toy`; unknown keys use the default.
- `?debug=1` enables the flight pause, holds the airplane still until Play (as `?gui=1` does; see [Experience](EXPERIENCE.md#play-action)), and is the only case that downloads `FlightPauseDebug` and `OrbitControls`. After the play intro, **P** freezes the airplane while global time keeps running and switches the camera to `OrbitControls`. See [Experience](EXPERIENCE.md#debug-flight-pause). `window.__INFINITE_WORLD__.getDebugStats()` reports the pause state.
- `?dpr=<ratio>` pins the renderer pixel ratio (clamped to `0.5`–`2`) and turns the adaptive resolution off, for screenshots and benchmarks; the `?gui=1` **Performance** folder toggles **Adaptive resolution** and sets **Minimum pixel ratio** (see [Rendering](RENDERING.md#scene-setup)).
- `window.__INFINITE_WORLD__.getRenderStats()` reports frame intervals, main-thread time per frame-loop stage, the draw calls and triangles of the whole last frame, and GPU time where the browser has the timer extension; the first call starts the GPU timing. See [Frame Telemetry](QUALITY.md#frame-telemetry) before comparing numbers.
